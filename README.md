# Business diagnosis website

A fast, accessible, multi-page website. It's plain HTML, CSS and a little JavaScript, generated by a small build script with **no dependencies**. You only need Node.js (version 18 or later) to build it.

## Quick start

```bash
node build.js           # builds the site into dist/
node tests/check.js     # runs the automated checks
node build.js --serve   # builds, then previews at http://localhost:8080
```

In local preview the forms show a "could not be sent" message. That's deliberate: there's no form backend on your computer, and the site never pretends a message was sent.

## Change the brand, prices and contact details

Everything you're likely to change lives in **`site.config.json`**:

| Setting | What it does |
|---|---|
| `brand.name` | The company name everywhere on the site. The current working name is Gainora. Change it and rebuild. |
| `brand.legalName`, `brand.address`, `brand.companyNumber` | Shown in the footer when filled in. Leave empty until you have them. |
| `site.url` | Your live address, e.g. `https://www.example.co.uk`. Turns on canonical URLs, `sitemap.xml` and structured data. |
| `contact.email` | Shown on the contact page and in the footer, and used in form error messages. |
| `contact.responseTime` | The reply time you promise, e.g. "within two working days". Only promise what you can keep. |
| `contact.bookingUrl` | Optional call-booking link (Cal.com, Calendly). Adds a "Book a short call" button. |
| `prices.*` | All public prices. |
| `forms.provider` / `forms.endpoint` | How form submissions are delivered (see below). |
| `founder.*` | Optional founder block on the About page. Leave `name` empty to hide it. |
| `legal.lastUpdated` | Date shown on the legal pages. |

Then run `node build.js` again.

Page copy lives in `src/pages/*.html`. Shared header, footer and closing call to action are in `src/partials/`. Styles and design tokens are in `src/assets/styles.css`, with the colours and type scale at the top.

## The shop: selling the course, agents and digital products

The Shop page (`/shop/`) and the homepage's shop section are built from `shop.items` in `site.config.json`. Each item has a name, price, features and a **status**:

| Status | Badge | Button | Takes payment? |
|---|---|---|---|
| `available` | Available now | "Buy now · £49" (or your `buttonLabel`) → your Stripe link | Yes |
| `preorder` | Pre-order | "Pre-order · £49" → your Stripe link, plus your `deliveryNote` and refund promise | Yes |
| `pilot` | Pilot sign-ups open | "Join the pilot" → free sign-up form | No |
| `early-access` | Early access | "Join early access" → free sign-up form | No |
| `waitlist` | Coming soon | "Join the waitlist" → free sign-up form | No |

**To start selling an item:**
1. In Stripe, create a Payment Link for the product (Stripe dashboard → Payment Links). Use a recurring price for agents.
2. Paste the link into the item's `checkoutUrl`.
3. Change its `status` to `available`, or to `preorder` with a `deliveryNote` such as "Delivered by 30 November 2026".
4. Run `node build.js`.

The build **stops with an error** if an item is set to `available` or `preorder` without a payment link, so you can't publish a dead Buy button. `featured: true` puts an item on the homepage; four featured items fit best.

Set up delivery before switching an item to `available`: Stripe's after-payment redirect or email, plus access to the product or course. Selling something you can't yet deliver is a pre-order and has to be labelled as one.

## Forms

There are two forms: `enquiry` (contact page) and `shop-signup` (shop sign-ups for the course, agents and products, with the chosen item recorded). Every form has:
- labels;
- validation with clear messages;
- a hidden spam trap;
- a consent checkbox;
- real success and error states.

A success message only appears when the form service confirms it received the message.

**Option A: Netlify Forms (default, `"provider": "netlify"`).** Deploy to Netlify and the forms are detected automatically. Then go to Site configuration → Forms → Form notifications and add an email notification for each form. Send yourself a test before going live.

**Option B: any other host with Formspree or a similar service.** Create a form at formspree.io, then set:

```json
"forms": { "provider": "formspree", "endpoint": "https://formspree.io/f/your-id" }
```

**If neither is set up**, the form tells visitors it isn't connected and shows your email address instead of losing their message.

Forms never connect to any internal system. Submissions go only to the form service you choose.

## Deploying

**Netlify (simplest).** Put this folder in a GitHub repository and import it in Netlify. `netlify.toml` already sets the build command (`node build.js && node tests/check.js`) and the publish folder (`dist`). The deploy fails if the checks fail. Alternatively, run `node build.js` locally and drag the `dist` folder onto app.netlify.com/drop.

**Anywhere else.** Upload the contents of `dist/` to any static host (Cloudflare Pages, Vercel, GitHub Pages or traditional hosting). `dist/_headers` sets security headers on Netlify and Cloudflare Pages. On other hosts, configure the same headers in the server settings.

## What the checks test (`tests/check.js`)

- **Metadata:** every page has a unique title, a meta description of sensible length, `lang="en-GB"` and exactly one `<h1>`.
- **Links:** no broken internal links or in-page anchors.
- **Accessibility:** every form control has a label, and every image has alt text.
- **Forms:** each form is registered, has a spam trap, a form name and a consent checkbox.
- **Security:** no inline styles, which the Content Security Policy would block.
- **No invented claims:** no testimonials, "trusted by", client counts, awards, percentage results, guarantees or urgency language.
- **Scope:** no marketing management services offered, and the private internal system is never mentioned.
- **Nothing purchasable yet:** no buy buttons on the products or course pages.
- **Config:** prices and the brand name come from the config.

## Accessibility and performance notes

- Semantic HTML, a skip link, a keyboard-accessible mobile menu (Escape closes it) and visible focus styles.
- Respects reduced-motion settings. There is no autoplaying animation.
- About 25 KB of CSS and 6 KB of JavaScript, with no frameworks or tracking scripts.
- Fonts come from Google Fonts. To self-host them, which also stops visitors' IP addresses going to Google, download Newsreader and Public Sans as woff2 files into `src/assets/fonts/`, add `@font-face` rules to the top of `styles.css`, and remove the Google Fonts links from `src/layout.html` and from the Content-Security-Policy in `src/_headers`.
