# Gainora website

The public site at gainora.co.uk: four packages with fixed prices, the £495 Business Audit, a 15-minute diagnostic booking page and the Business improvement calculator. Plain HTML, CSS and a little JavaScript, generated by a small build script with **no dependencies**. You only need Node.js (version 18 or later).

## Quick start

```bash
node build.js           # builds the site into dist/
node tests/check.js     # runs the automated checks (about 1,000 of them)
node build.js --serve   # builds, then previews at http://localhost:8080
node tools/make-preview.js   # a copy with relative links, for a private preview on a sub-path
```

In local preview the booking form shows a "could not be sent" message. That's deliberate: there's no form backend on your computer, and the site never pretends a message was sent.

## Where things live

| What | Where |
|---|---|
| Brand, contact details, booking link, **every price**, founding-offer switch, demo number | `site.config.json` |
| Calculator starting figures and their sources | `calculator.json` |
| Page copy | `src/pages/*.html` (one file per page, with a meta comment at the top) |
| Header, footer, closing call to action | `src/partials/` |
| Styles and design tokens (black and champagne) | `src/assets/styles.css` |
| Behaviour: menu, forms, reveal | `src/assets/main.js`; calculator `calc.js`; home rail `home.js`; booking page `book.js` |
| Redirects for removed pages | `netlify.toml` and `src/_redirects` (keep them in step; the tests check) |
| Security headers and Content Security Policy | `src/_headers` |

Prices appear on the pages only through `{{prices.…}}` tokens, and the checks fail if a page shows a price that isn't one of them. The build reads the current prices from Gainora admin → Prices (`https://app.gainora.co.uk/api/prices`); pressing **Save and update the website** there rebuilds this site. If the admin can't be reached, the build uses the prices in `site.config.json`, so keep those as the fallback (`node build.js --offline` builds with them only).

## Switches in `site.config.json`

- `founding.show`: `true` shows the founding offers on the packages page. Off by default; mention them on calls.
- `demo.phone`, `demo.phoneHref`, `demo.recordingUrl`: set all three and the "Ring our receptionist" block appears on the home page. The build refuses a number without a recording.
- `contact.bookingUrl` and `contact.bookingEmbedUrl`: the Google Calendar appointment schedule. The embed URL is the schedule link with `?gv=true`; if it's empty the booking page shows the form first and promises times by email.

## The booking form

One form, `diagnostic`, on `/book/`. It collects name, business, email, mobile, website, type and size of business, how enquiries come in, rough volume, which package caught their eye, what isn't working, and consent. It has labels, validation, a hidden spam trap and honest success and error states. A success message only appears when Netlify confirms it received the submission.

**Netlify Forms (default).** Deploy to Netlify and the form is detected automatically. Then: Site configuration → Forms → Form notifications → add an email notification. Send yourself a test before going live. Later, the same screen can add an outgoing webhook to the Capture & Convert inbox so enquiries land there too.

## The calculator

`calculator.json` holds every starting figure. Each has a `basis`: `research` (with a `source` key that must exist in `sources`, with the URL we opened), `assumption` (a starting point the visitor is told to change) or `yours` (the visitor's own number). The page shows a Research or Your estimate badge on every input, the source under it, and lists all sources at the bottom. The arithmetic is one pure function in `src/assets/calc.js`, tested in `tests/calc.test.js`. Prices are injected at build time from `site.config.json` into `dist/assets/calc-data.js`. Nothing the visitor types is stored or sent.

## Deploying

**Netlify.** Put this folder in a GitHub repository and import it in Netlify. `netlify.toml` sets the build command (`node build.js && node tests/check.js`) and the publish folder (`dist`). The deploy fails if the checks fail. Or run `node build.js` locally and drag the `dist` folder onto app.netlify.com/drop; `dist/_redirects` and `dist/_headers` are honoured either way.

## What the checks test (`tests/check.js`)

- Metadata: unique titles, meta descriptions of sensible length, `lang="en-GB"`, exactly one `<h1>`.
- Links and anchors resolve, including cross-page anchors to the packages.
- Accessibility: labels on every control, alt text on images, titles on iframes.
- The booking form is registered with Netlify, has a spam trap and a consent checkbox, and all intake fields are present.
- Security: no inline styles or scripts (the Content Security Policy blocks them); the CSP allows the calendar embed.
- Offer rules: fixed prices only (no "from", no trailing "+"), prices marked ex-VAT, every price on a page matches `site.config.json`, no "illustrative", "businesses" not "small businesses", not positioned for one type of business, outcome before "AI", the old call-to-action wording gone.
- Honesty: no testimonials, "trusted by", client counts, awards, percentage results, guarantees or urgency language.
- Nothing for sale outside the five offers; no payment links on the site.
- Redirects: every removed address has a 301 in both redirect files to a page that exists; removed pages aren't built.
- Calculator: every research default has a source with a URL, every source is listed on the calculator page, prices come from config, and the arithmetic matches worked examples.
